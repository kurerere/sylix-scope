# 0004: 网络诊断模块通信通道与按需分层采集架构

## Context
SylixOS 嵌入式实时系统运行在资源受限的目标硬件上。执行 `netstat` 系列命令（包括 `netstat -a`, `netstat -i`, `netstat -r`, `netstat -s`）涉及大量网络套接字、路由与接口状态文本的导出与序列化，在目标板 Telnet 终端上具有明显的 CPU 与带宽占用。若将其无差别地塞入高频后台主监控循环（Monitor Engine），会导致嵌入式目标板的监控采样抖动并增大通信压力。

## Decision
我们决定采用**分层按需采集架构（Layered On-Demand Acquisition）**：
1. **通信通道隔离**：网络模块的数据拉取通过独立的 Command Session（独立的 Telnet 异步连接）执行，与主监控引擎（Monitor Engine）的周期性 CPU/内存采样完全解耦，互不干扰。
2. **默认按需拉取 + 可选受控自动刷新**：套接字与路由表等大体量明细默认在进入网络看板或用户点击刷新时执行；同时界面提供自动刷新开关，由用户显式配置轮询间隔（如 3s、5s、10s、30s）。
3. **Rust 原生结构化解析**：由 Rust 后端执行命令并将原始文本解析为强类型结构体（`NetInterface`、`NetSocket`、`RouteEntry`、`NetStatistics`），前端直接消费结构化数据。

## Rationale
1. **保护嵌入式目标板性能**：避免无节制的高频套接字扫描对实时控制系统内核造成负担。
2. **保障数据解析性能与健壮性**：Rust 原生正则与状态机解析速度极快，且能有效隔离平台文本格式异常，为后续接入 MCP 工具提供统一的强类型接口。
3. **用户可控的观测成本**：工程师根据当前现场网络调试需要按需查询或配置刷新频率，符合专业系统监控工具的实用主义。
